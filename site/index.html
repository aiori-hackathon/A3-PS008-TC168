OPTIONAL · GNS3 LAB

Connect a three-router lab.

Use an isolated lab with supported router images and reachable management access. GNS3 setup depends on your local image and controller configuration.

1Create and start the routers

In GNS3, create a project with R1, R2, and R3. Connect R1–R2 and R2–R3, start the nodes, and confirm the GNS3 controller is reachable.

2Configure management and SSH

Assign reachable management IP addresses, enable SSH, and verify host keys. Use a permitted IOS-compatible image for the IOS adapter workflow.

3Configure the adapter inventory

From the clone, copy the inventory example to .ps008/gns3-inventory.json. Set project and node IDs, management addresses, usernames, and credentials through environment variables.

4Capture, preview, and test

Start the dashboard with inventory configured. Capture router evidence, inspect routes, preview a supported static-route request, and review the candidate. Use GNS3 link capture and Wireshark to inspect ICMP packets.

PACKET TEST COMMANDS

Test each hop. Explain the result.

Run these examples in the three-router OpenWrt lab after assigning 10.0.1.1/24 to R1, 10.0.1.2/24 and 10.0.2.1/24 to R2, and 10.0.2.2/24 to R3. The router commands below use the Linux shell.

01 · R1 console

Check the source router

ip -4 address show
ip -4 route show
ip route get 10.0.2.2

Confirm R1 has its link address and selects R2 at 10.0.1.2 as the next hop to R3.

02 · R1 console

Test the first link

ping -c 4 -W 2 10.0.1.2

Replies here show R1 can reach R2. If this fails, check the R1–R2 link and addresses before testing R3.

03 · R1 console

Test the full path to R3

ping -c 4 -W 2 10.0.2.2

Read the transmitted and received counts. A full-path reply needs a forward path through R2 and a return path to R1.

04 · R2 console

Check the transit router

ip -4 address show
ip -4 route show
sysctl net.ipv4.ip_forward

R2 should see both connected networks. A forwarding value of 1 means IPv4 packet forwarding is enabled.

05 · R3 console

Check the reply path

ip -4 route show
ip route get 10.0.1.1
ping -c 4 -W 2 10.0.1.1

Confirm R3 sends replies toward R2 at 10.0.2.1. A missing return route can make R1’s full-path ping fail.

06 · OpenWrt lab setup

Set the two static routes

On R1:

ip route replace 10.0.2.0/24 via 10.0.1.2

On R3:

ip route replace 10.0.1.0/24 via 10.0.2.1

Repeat the ping. These manual lab commands are separate from the IOS approval workflow.

07 · Wireshark

Locate the ICMP packets

icmp
icmp && ip.addr == 10.0.2.2

Start a GNS3 capture on each link, then enter either line in Wireshark’s display filter. Compare Echo requests with Echo replies.

08 · Dashboard

Save time-stamped evidence

Open local GNS3 dashboard ↗Refresh live routers → Send R1 → R3 ping → Export lab evidence JSON

With the local lab connected, the dashboard records observed routes and the actual ping count. Report the captured result, including failures.
