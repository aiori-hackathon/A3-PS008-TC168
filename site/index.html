A CLEAR CHANGE JOURNEY

From operator intent
to verified outcome.

Each stage shows what the system knows and what still needs a human decision.

01

Describe the change

Choose a source router and destination prefix. NexaRoute builds a structured route request.

02

Inspect the impact

Compare modeled forwarding paths before and after the candidate. Review validation results and warnings.

03

Approve or reject

Review the exact supported command. An explicit approval is required before the adapter deployment flow.

04

Verify and record

For the supported IOS adapter path, read back the route, probe connectivity, and preserve operation evidence.

OPTIONAL · GNS3 LAB

Connect a three-router lab.

Use an isolated lab with supported router images and reachable management access. GNS3 setup depends on your local image and controller configuration.

1Create and start the routers

In GNS3, create a project with R1, R2, and R3. Connect R1–R2 and R2–R3, start the nodes, and confirm the GNS3 controller is reachable.

2Configure management and SSH

Assign reachable management IP addresses, enable SSH, and verify host keys. Use a permitted IOS-compatible image for the IOS adapter workflow.

3Configure the adapter inventory

From the clone, copy the inventory example to .ps008/gns3-inventory.json. Set project and node IDs, management addresses, usernames, and credentials through environment variables.

4Capture, preview, and test

Start the dashboard with inventory configured. Capture router evidence, inspect routes, preview a supported static-route request, and review the candidate. Use GNS3 link capture and Wireshark to inspect ICMP packets.

PACKET TEST COMMANDS

Try the route from a router console.

These commands apply to the example OpenWrt lab after interface addresses, forwarding, and routes are configured.

Inspect R1 addresses and routes

ip -4 address show
ip -4 route show
ip route get 10.0.2.2

Send four packets from R1 to R3

ping -c 4 -W 2 10.0.2.2

Check the received packet count. On the GNS3 dashboard, click Send R1 → R3 ping to record a timestamped result.

Inspect packets in Wireshark

Display filter: icmp

Start captures on both GNS3 links and repeat the ping. Echo requests are outgoing probes; Echo replies are responses.

CLEAR PRODUCT SCOPE

Focused on IPv4 static route reviews.

The software twin supports repeatable planning scenarios. The GNS3 OpenWrt panel provides live observation and ping testing. The approval-gated adapter targets IOS-compatible routers; live IOS deployment should be validated in a configured lab.
